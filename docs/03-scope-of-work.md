## Why these sections exist

### Primary audience: AI agent developers
They need: quickstart, SDK reference, error handling, integration guides.

### Secondary audience: framework plugin users (Claude Code, OpenClaw)
They need: 1-command install, zero-config, "it works" experience. The quickstart leads with these two.

### Tertiary audience: ops/team leads
They need: dashboard guides, policy builder, approval workflows, audit log.

### Fourth audience: AI agents themselves
They need: llms-skill (structured, token-efficient), llms.txt (auto-generated by Mintlify).

## Why Mintlify

1. Privy (competitor) uses it, so it's proven for web3 developer docs
2. Auto-generates llms.txt and llms-full.txt (critical for GEO)
3. OpenAPI playground auto-generated from spec
4. GitHub auto-deploy (push to master -> live in 30s)
5. Built-in search, feedback (thumbs, suggest edit, raise issue)
6. MDX components match our needs (CodeGroup, Tabs, Cards, callouts)

## Why separate repository

1. Documentation has different deploy cadence than the product
2. Non-engineers (DevRel, marketing) can contribute without touching product code
3. Mintlify connects to a single repo
4. Keeps mandate monorepo focused on product
